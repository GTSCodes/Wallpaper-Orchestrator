# C8.3 release reliability — Windows acceptance, backup and release checklist

**Target:** `v0.8.0b3`. **Prerequisite:** merged C8.3.0 and C8.3.1.
Do not publish until this checklist passes on Windows 10/11.

## Scope and guarantees

- A second GUI launch activates the existing window, including from tray.
- A per-user Qt local IPC channel controls the GUI; the automation agent's
  independent named Windows mutex remains separate.
- Inno Setup requests a cooperative agent stop and GUI exit before overwriting
  binaries; older GUIs fall back to Restart Manager's `CloseApplications=yes`.
- The new installer performs a checked state backup followed by a checked
  `--repair-startup` before offering automatic launch. Explicit pause/opt-out
  settings are still respected.
- SQLite schema remains at **version 3**. No database migration is required by
  this release. Existing v1/v2 databases receive a WAL-consistent backup before
  the normal additive catalogue migration.
- Every user backup is new and independent of the write-once **First Restore
  Point**. Wallpaper image files and saved user data are not deleted.
- Builds check version consistency and pin Windows CI Python dependencies.
  SHA-256 checksums accompany release candidates and tag-only GitHub pre-releases.

## Applying the one-piece patch

Start from clean `main`, **after** C8.3.1 is merged:

```powershell
git status --short
git switch main
git pull --ff-only origin main
git switch -c feat/c8.3-release-reliability

$patch = 'PASTE_THE_ACTUAL_DOWNLOADED_PATCH_PATH'
Test-Path $patch
git apply --check $patch
git apply $patch
python scripts/check_version.py
python -m unittest discover -s tests -q
git -c core.whitespace=cr-at-eol diff --check
git diff --stat
```

Use File Explorer **Copy as path**. Downloads might be under `Favorites\Downloads`;
never assume `%USERPROFILE%\Downloads`. If `git apply --check` fails, stop and
check your branch and patch path. Do not use `--force` or destructive resets.

## Build, self-test and installer

Close any old GUI, installed/portable/background-agent processes. Only rename
old output if no build process is using it:

```powershell
if (Test-Path '.\dist\WallpaperOrchestrator') {
    Rename-Item '.\dist\WallpaperOrchestrator' (
        'WallpaperOrchestrator-backup-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
}
.\scripts\build_windows.ps1
$exe = (Resolve-Path '.\dist\WallpaperOrchestrator\WallpaperOrchestrator.exe').Path
$p = Start-Process -FilePath $exe -ArgumentList '--self-test' -PassThru -Wait
$p.ExitCode  # must be 0
.\scripts\build_installer.ps1
```

Inno Setup 6 or 7 can compile the installer; `-IsccPath` accepts the actual
`ISCC.exe` if not auto-detected. Do not test installed and portable agents
simultaneously. GitHub CI builds run in isolated runners and **do not** replace
manual interactive installer tests.

| Test | Expected outcome |
| --- | --- |
| Fresh standard-user install | Installer completes without needing admin rights |
| First GUI launch | Setup opens; First Restore Point captured exactly once |

| Close GUI to tray; launch again | Original hidden window reappears, no duplicate |

### Check restore-point invariance

Before/after an upgrade, read the hash of the same file:

```powershell
$first = Join-Path $env:LOCALAPPDATA 'WallpaperOrchestrator\wallpaper-first-restore-point.json'
Get-FileHash -LiteralPath $first -Algorithm SHA256
```

Do not delete, edit or overwrite this file. The installer backup is independent
of the wallpaper restoration function.

## User-state backups and recovery

Backups live at `%LOCALAPPDATA%\WallpaperOrchestrator\backups\backup-*` and
contain: `catalog.sqlite3` (online SQLite backup), persistent JSON settings,
optionally `qt-settings.reg` (HKCU QSettings), and `manifest.json` with hashes.
No original wallpaper image is included. A fresh user with no settings may not
need a backup. The installer checks its `--backup-user-data` result and refuses
**automatic launch** if backup or startup repair fails.

To recover, **first** exit all GUI and agent instances (including installed
and portable copies) and make an independent copy of the current data folder.
Then inspect the backup's `manifest.json`. A support-assisted restoration can
rename the current `catalog.sqlite3`, its `-wal`/`-shm` sidecars if present,
and relevant JSON to a separate safety folder, then copy their counterparts
from the verified backup. Do not merge an old SQLite database with newer WAL
files. Restore `.reg` registry data only with explicit user consent and after
review. **Never replace the First Restore Point as a routine rollback.**

No automatic destructive rollback is performed by the application or installer.

## Primary-account installation error

An Inno Setup `Error 5: Access is denied` when creating an `is-*.tmp` directory
occurred on the developer's main Windows account even though ordinary directory
creation worked. The same CI installer succeeded on a separate local Windows
account. This is not proof that every other Windows installation will pass.
Before public release, test on an additional computer/account; investigate
process-specific access denial using ProcMon or security event logs if it recurs.
**Do not disable Defender, SmartScreen or change broad Temp-folder ACLs.**

## Pull request, tag and GitHub pre-release

Only after local Windows acceptance and green GitHub Actions:

```powershell
git status --short
git diff --cached --stat
git add -- .github/workflows/windows-portable.yml README.md docs/C8.3-RELEASE-VALIDATION.md
# Stage the other *reviewed* files shown by the patch manifest too.
git diff --cached --check
git commit -m "feat: complete C8.3 release reliability"
git push -u origin feat/c8.3-release-reliability
```

Create a PR, merge it after the Windows CI succeeds and the installer has been
manually verified. Then update `main` and, **when ready to publish**, tag the
merged tested commit (do not re-tag old beta releases):

```powershell
git switch main
git pull --ff-only origin main
python scripts/check_version.py --tag v0.8.0b3
git status --short
git tag -a v0.8.0b3 -m "Wallpaper Orchestrator 0.8.0 Beta 3"
git push origin v0.8.0b3
```

**Pushing the matching tag automatically creates a GitHub pre-release only if**
the Windows packaging job succeeds. Pushing a branch or merging into `main`
only uploads Actions artifacts and **does not publish a release**.
The tag-build releases `Windows-portable.zip`, `Windows-Setup.exe` and
`SHA256SUMS.txt`. They may be unsigned and are not bit-for-bit reproducible
without pinning the compiler/runner image as well as Python requirements.

## Opt-in diagnostics

In the GUI, choose **Help → Export redacted diagnostics…**, select a local ZIP
path, and review it before sharing. The ZIP contains only a version/platform
summary and allowlisted, size-limited, redacted startup logs. It never contains
wallpapers, database, profile JSON, schedules or images and is never uploaded
by the application.
