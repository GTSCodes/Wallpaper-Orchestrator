# C8.2.1 — Safety Improvements: test and acceptance guide

**Release status: source patch for testing only. Do not merge into `main` or publish as stable yet.**

## Scope

1. **Excluded images:** In Library, select one or more images, click **Remove selected from collection…**. Manually added images lose manual collection membership. Linked-folder images become per-collection exclusions. The physical files are never deleted. Under **Library tools → Excluded images…**, select and restore an exclusion. Auto-scans and the wallpaper selector respect exclusions.
2. **Restore previous wallpapers:** The app captures the wallpapers for connected displays before its **first wallpaper change with this patch installed**. Use **Setup → Save current wallpapers as restore point…** to explicitly capture or replace the baseline. Use **Setup → Restore previous wallpapers and pause automations…** to stop the background worker, disable Windows sign-in startup, pause interval/daily/seasonal automation globally, and restore saved images for connected displays. Rules, tags, collection links and files remain saved.

**Important:** Existing beta users cannot recover the Windows wallpaper baseline from before this feature was installed. First capture is the state visible just before the first change *after installation of this patch*. You can deliberately save the desired baseline from the Setup menu before testing shuffle.

A restore point stores image paths, **not copies of image files**, and does not yet preserve Windows slideshow/style/colour/theme settings. Disconnected monitors and missing original image paths are reported, not overwritten. Reconnecting later does not automatically apply the snapshot.

## Before applying on your Windows development machine

1. On GitHub merge your verified `fix/monitor-automation` branch into `main` via a pull request (review diff, no force push).
2. In VS Code, ensure `git status --short` is empty, then run:
   ```powershell
   git fetch origin
   git switch main
   git pull --ff-only origin main
   git switch -c feat/c8.2.1-safety
   ```
3. Stop the GUI and independent agent. Back up `%LOCALAPPDATA%\WallpaperOrchestrator` while no database-writing processes are running (this preserves SQLite and its WAL contents). Keep the original wallpaper folders untouched.
4. Download `WallpaperOrchestrator-C8.2.1-Safety.patch` and apply it from the repository root:
   ```powershell
   $patch = "$env:USERPROFILE\Downloads\WallpaperOrchestrator-C8.2.1-Safety.patch"
   git apply --check $patch
   git apply $patch
   git status --short
   ```
   If the check fails, **do not force the patch**, and request an adapted patch for your working tree.
5. Run automated tests:
   ```powershell
   python -m unittest discover -s tests -q
   ```
   The development package passed **174 tests** on Linux (one test skipped in earlier Windows runs is environment dependent). Python syntax was checked; Windows GUI and bundled execution are still unverified.
6. Stop the old portable/installed GUI and agent. Rename the existing `dist\WallpaperOrchestrator` folder (don't delete it), then run `.\scripts\build_windows.ps1`.
scripts\build_windows.ps1` (replace the control character if copying from this file; the correct command is `./scripts/build_windows.ps1` in PowerShell with backslashes).

## Acceptance checklist

- [ ] Before applying any wallpaper, explicitly save a known restore point from **Setup**. Ensure at least two different wallpapers and an existing interval are available for testing.
- [ ] Import a manually dragged image outside all linked folders. Remove it from the collection; it disappears; its file remains on disk; **Excluded images** stays empty for that removal.
- [ ] Scan a linked folder. Remove one of its images. A warning explains that its file stays on disk and the collection excludes it.
- [ ] Scan the linked folder again (including with Auto-scan enabled). The excluded image remains hidden and is not selected during shuffling from that collection.
- [ ] Open **Library tools → Excluded images…**, restore the image, and verify it appears again. Exclusions in Collection A do not affect Collection B.
- [ ] Exclude a linked-folder image and then delete the original image using File Explorer. With the folder available, scan and verify the exclusion is automatically cleaned up.
- [ ] Temporarily disconnect an external folder/drive. A scan **must not** erase exclusions just because the folder is unavailable.
- [ ] Test the same behaviour with portrait and landscape monitor assignments and seasonal/intelligence rules.
- [ ] Enable interval automation, observe a shuffle, then use **Setup → Restore previous wallpapers and pause automations…**. Saved original wallpapers should return to connected displays, and all scheduled changes should stop even when the GUI exits.
- [ ] Confirm saved interval, daily and seasonal rules still exist, but the global pause remains on. Re-enable scheduling only when ready.
- [ ] Restart Windows and check the restored wallpaper remains unchanged (the background worker must not restart unexpectedly).
- [ ] Unplug a monitor during restoration; another display must still restore. Missing image files must be reported, not deleted or silently replaced.
- [ ] Rebuild the installer using Inno Setup; test upgrade and retention of catalogue/settings on a separate Windows user/device before a new GitHub beta release.

## Technical notes and rollback

- The database schema upgrades from `user_version=2` to `3` to add `collection_exclusions`. The migration is additive and preserves existing image/collection IDs. **An older v0.8 beta executable will refuse to open a v3 catalogue**. Back up `%LOCALAPPDATA%\WallpaperOrchestrator` before testing; restoring an old executable alone is not a rollback.
- Excluded images are filtered by `list_collection_images` and `list_image_collections` so automatic selection and other consumer code do not see them. All filenames and image contents stay untouched.
- The restore point is `wallpaper-restore-point.json` in the same per-user application data folder as automation.json. It is written atomically and is never overwritten silently.
- The global `paused` flag is already honoured by both foreground and background schedulers. Restoration also disables the background startup preference and waits for the agent to stop before applying restored images.
- Do not merge the safety branch into main until the actual Windows UI, background-agent, and clean-install/upgrade tests pass.
