# Wallpaper Orchestrator — C8.2.2 reliability patch

This patch builds **on top of C8.2.1** (SQLite schema v3, excluded images, restore points). It is not a replacement for C8.2.1 or a ready-made Windows executable. Do not downgrade the database or overwrite personal settings.

## What changed

- **First Restore Point:** On the first launch of this version, capture a new, immutable `wallpaper-first-restore-point.json` in `%LOCALAPPDATA%\WallpaperOrchestrator`, before GUI timers, the setup wizard, or wallpaper changes. Also protect every `IDesktopWallpaper.SetWallpaper` call with a capture-once guard. The Setup menu offers **Restore First Restore Point and pause automations**.
- **Custom restore point:** The previous `wallpaper-restore-point.json` is preserved as an independently editable custom point. Saving a custom point can never replace the first point.
- **Background default:** On a genuinely new installation, the setup wizard shows **Keep enabled automations running after closing the app (start with Windows)** pre-checked. Pressing **Finish** applies the preference, whether or not an interval was created. **Skip** does not silently apply settings. Existing users' saved opt-out and a restoration pause are respected.
- **Old agent compatibility:** New workers write their actual executable path and supported SQLite catalogue schema to `background-status.json`. When an enabled new GUI encounters a live worker from a different executable or old schema, it asks that worker to stop, repairs the per-user startup command and launches the current worker. Failure to stop the old agent blocks replacement, avoiding competing workers. The installer repair command cleans obsolete startup registration when automation is off or paused.
- **Packaged self-test:** Now rejects a bundle using an old catalogue schema.

**First Restore Point limitation:** Existing beta users can only capture the desktop that exists when they first launch C8.2.2. Wallpapers overwritten by an earlier beta version cannot be reconstructed. The snapshot stores wallpaper image paths, not every Windows theme/slideshow/position preference. Normal users cannot overwrite the first snapshot from the GUI; changing files outside the application is not preventable.

## 1. Safely commit the verified C8.2.1 source

Run from your repo in VS Code (PowerShell):

```powershell
git branch --show-current
git status --short
python -m unittest discover -s tests -q

git add -- src/wallpaper_orchestrator/catalog.py src/wallpaper_orchestrator/library_view.py src/wallpaper_orchestrator/gui.py src/wallpaper_orchestrator/platforms/windows.py src/wallpaper_orchestrator/restore_points.py tests/test_c6_library.py tests/test_c8_2_safety.py docs/C8.2.1-SAFETY-TESTING.md
git diff --cached --stat
git -c core.whitespace=cr-at-eol diff --cached --check
git commit -m "feat: add safe collection exclusions and wallpaper restoration"
git push -u origin feat/c8.2.1-safety
```

Review `git diff --cached --stat` and avoid staging `.venv`, `dist`, `build`, databases, wallpaper files or local settings. **Do not force-push** or reset other changes. If your C8.2.1 files were already committed, skip the commit.

## 2. Create a separate reliability branch and back up your settings

```powershell
git switch feat/c8.2.1-safety
git switch -c feat/c8.2.2-reliability

$source = Join-Path $env:LOCALAPPDATA 'WallpaperOrchestrator'

```

**Close all installed and portable Wallpaper Orchestrator GUI/agent processes BEFORE the backup.** Then:

```powershell
Copy-Item -LiteralPath $source -Destination $backup -Recurse
Write-Host "Backup at $backup"
```

If the source folder is missing, confirm your local settings path before proceeding. The backup must be complete and kept until testing is finished.

## 3. Apply the patch

Download `WallpaperOrchestrator-C8.2.2-Reliability.patch` to your Downloads folder.

```powershell
$patch = Join-Path $env:USERPROFILE 'Downloads\WallpaperOrchestrator-C8.2.2-Reliability.patch'
git apply --check $patch
# Only if check succeeds:
git apply $patch
python -m unittest discover -s tests -q
git -c core.whitespace=cr-at-eol diff --check
```

The expected reference result is **188 tests run, no failures** in the prepared cross-platform source snapshot. Platform-dependent skips may differ. Unit tests are not proof of Windows behaviour.

## 5. Upgrade the actual installed copy (required to fix the v2 worker warning)

An old *installed* beta can still run in `%LOCALAPPDATA%\Programs\WallpaperOrchestrator` even if the new portable copy works. That old agent cannot read SQLite catalogue v3. A portable rebuild **does not upgrade the installed executable**.

Install Inno Setup 7 (already present on your PC) and run:

```powershell
$compiler = Get-ChildItem -Path @(
  'C:\Program Files\Inno Setup*\ISCC.exe',
  'C:\Program Files (x86)\Inno Setup*\ISCC.exe',
  "$env:LOCALAPPDATA\Programs\Inno Setup*\ISCC.exe"
) -ErrorAction SilentlyContinue | Select-Object -First 1 -ExpandProperty FullName
.\scripts\build_installer.ps1 -IsccPath $compiler
```

Before installing the new `dist\WallpaperOrchestrator-Setup.exe`, exit all portable/installed GUI and agent instances. Run the installer to update your installed copy, launch **only** the installed program from Start, then verify background automation and the registry command. The installer `--repair-startup` pathway updates the startup command or removes an old entry when paused. Avoid running the old portable and new installed copies simultaneously.

## 6. Acceptance checklist (Windows)

1. **First capture:** With a first-time profile or clean test user, note the original wallpaper on each physical display. Open the new app; confirm `wallpaper-first-restore-point.json` was created **before shuffling**. `First Restore Point` matches the original wallpapers.
2. **Permanent:** Change wallpapers, save/update a *custom* restore point, close/relaunch, and verify the First Restore Point file still has the original monitor-to-image mapping and capture timestamp.
3. **Restore:** Use **Restore First Restore Point and pause automations**. Verify connected displays return to their first captured wallpapers, automation settings show `paused=True, background_enabled=False`, and no interval changes occur after closing the GUI and rebooting.
4. **Default on new install:** In a genuinely fresh Windows account, check that background-at-sign-in is preselected and applied on **Finish**. Create an enabled interval and verify it runs after GUI exit and Windows sign-in.
5. **User preference:** Uncheck background mode in the wizard, finish, reopen it and ensure it stays unchecked. After Restore Previous Wallpapers, verify the app doesn't automatically re-enable it.
6. **Old agent upgrade:** Inspect running process paths and the `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `WallpaperOrchestratorAgent`. Reinstall/upgrade the **installed** copy and confirm no old version-2-schema warnings, no double agents, and current executable startup registration.
7. **Regression:** Verify all C8.2.1 exclusion tests still work, disconnected displays are skipped without stopping other automations, and existing wallpaper collections and rules remain unchanged.

If test 6 fails, capture the *full* `Get-CimInstance Win32_Process -Filter "name = 'WallpaperOrchestrator.exe'" | Select ProcessId,ExecutablePath,CommandLine` output and `%LOCALAPPDATA%\WallpaperOrchestrator\background-status.json`, without sharing private wallpaper paths. Avoid trying to downgrade the SQLite catalogue.
