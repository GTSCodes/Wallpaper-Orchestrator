# Wallpaper Orchestrator — C8.1 native executable launcher hotfix

## Evidence from the 13 November 2026 Windows screenshots

- Nuitka compiled a new executable (`WallpaperOrchestrator.exe`, 11:13:34) and the Python test suite passed 159 tests (one skipped).
- The new binary still failed `--self-test` with exit code `1`.
- The GUI reported that the background launcher did not exist and displayed a path ending in `dist\...\python.exe`.
- `background.py` in the C8.2 source used `sys.executable` when compiled, and checked that result as though it were the actual Windows application executable.

The failure is consistent with Nuitka exposing a synthetic/missing `python.exe` path in `sys.executable`. This hotfix calls the Windows `GetModuleFileNameW(NULL, ...)` API to find the running image instead. This is a source fix; the revised packaged executable must still be tested on Windows.

## Recommended approach: apply the patch to your existing C8.2 project

1. Exit Wallpaper Orchestrator and its tray icon, disable old background automation, and ensure there is no old agent process running. Preserve your library and application data.
2. Save your current source changes or make a backup. In the VS Code PowerShell terminal, navigate to your current project root (where `desktop.py` and `scripts` live):

   ```powershell
   cd 'C:\Users\kiero\Orchestrator\Wallpaper-Orchestrator'
   git status --short
   ```

3. Download `WallpaperOrchestrator-C8.1-AgentLauncher-Fix.patch` into Downloads. Run:

   ```powershell
   $patch = Join-Path $env:USERPROFILE 'Downloads\WallpaperOrchestrator-C8.1-AgentLauncher-Fix.patch'
   git apply --check $patch
   git apply $patch
   ```

   If `git apply --check` fails, stop and inspect the worktree before proceeding; do not force the patch. Instead extract the *full updated source ZIP* into a **new** folder and build there.

4. Rename the previous portable build folder rather than deleting it:

   ```powershell
   Rename-Item -Path '.\dist\WallpaperOrchestrator' -NewName 'WallpaperOrchestrator-BeforeHotfix'
   ```

   If no such folder exists, skip this command. If the folder is locked, exit the old GUI/background process.

5. Run the normal build (now runs Python tests and a native packaged self-test):

   ```powershell
   .\scripts\build_windows.ps1
   ```

   Expect **162 tests** (and 1 skip) in this snapshot. The build will **fail** if the packaged `--self-test` returns a nonzero exit code; the diagnostic is saved in `%LOCALAPPDATA%\WallpaperOrchestrator\self-test-startup-error.txt`.

6. Independently verify the newly built EXE:

   ```powershell
   $exe = (Resolve-Path '.\dist\WallpaperOrchestrator\WallpaperOrchestrator.exe').Path
   $p = Start-Process -FilePath $exe -ArgumentList '--self-test' -Wait -PassThru
   $p.ExitCode
   ```

   Expect `0`. If `1`, open:

   ```powershell
   notepad "$env:LOCALAPPDATA\WallpaperOrchestrator\self-test-startup-error.txt"
   ```

7. Launch the new EXE, enable background mode from Schedules > Manage all automations > Apply background setting, exit the GUI through the tray, then run:

   ```powershell
   Start-Process -FilePath $exe
   # After enabling background automation and exiting GUI:
   .\scripts\verify_windows_agent.ps1
   ```

   Visually verify wallpaper changes after the GUI exits; also test after Windows sign-in. Do not build the installer until this passes.

8. If launch still fails, open:

   ```powershell
   notepad "$env:LOCALAPPDATA\WallpaperOrchestrator\background-launch.log"
   ```

   It now logs both `sys.executable` and the actual Windows process executable.

## What changed

- `src/wallpaper_orchestrator/background.py`: gets executable from `GetModuleFileNameW`; no longer trusts the synthetic `sys.executable` for compiled mode.
- `src/wallpaper_orchestrator/desktop_entry.py`: packaged self-test compares against actual Windows process image and writes a traceback to `self-test-startup-error.txt` on failure.
- `tests/test_c8_installer_agent.py`: three new tests including this exact failure mode and an emulated Win32 API.
- `scripts/build_windows.ps1`: blocks copying/publishing failed standalone builds.
- `docs/C8-WINDOWS-TESTING.md`: updates verification instructions.

Validation in current environment: **162 unit tests, 0 failures**; the patch applies cleanly to the earlier C8.2 source. Actual Windows executable and background agent behaviour remain unverified until you rebuild and test on Windows.
